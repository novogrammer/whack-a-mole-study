# whack-a-mole-study ゲーム仕様

現在の仕様と実装の仕組みをまとめる。調整中の値は現状の値として記載し、未決定事項は末尾に分ける。音楽を選んだ理由や変更の経緯は[BGM・SEの作曲メモ](audio-composition-notes.md)を参照。

## 1. 目的・世界観

広告キャンペーン向けのカジュアルWebゲーム制作を想定し、Vite + TypeScript + Phaserで開発を学ぶ。

古典的なモグラ叩きをベースに、オリジナルキャラクターの表情・動き・効果音を楽しめるゲームを目指す。現在は仮グラフィックで、狙って叩く操作感と、叩いたときのリアクションを検証している。スコア・残り時間・タイトルと結果画面・BGM・SEを含む基本ループは実装済み。

世界観は菜園。ゲーム画面に世界観を説明する文章は置かず、背景・野菜・土・穴の周囲の装飾などの見た目で伝える。キャラクター設定や具体的な美術表現は、今後相談する。

## 2. ルールとプレイの流れ

### 基本ルール

- 穴は3列 × 3行の9マス。
- モグラの出現開始時刻は固定譜面、場所はプレイごとにランダムに割り当てる。
- 同じマスのチャレンジは重ねず、別マスでは同時出現を許容する。
- 1プレイ40チャレンジ。命中1回につき1点、満点は40点。
- 1チャレンジにつき加点は1回。空振り・見逃しでは得点を維持する。

### プレイ

スタートから結果表示までを「1プレイ」とする。BGMに合わせてイントロ4秒、本編32秒、終了表示2秒の順に進み、開始から38秒で結果画面へ移る。

| BGM開始から | 進行 |
| --- | --- |
| 0〜4秒 | イントロ。「よーい」を1秒表示し、その後「3・2・1」を1秒ずつ表示 |
| 4〜36秒 | 本編。譜面を開始し、残り時間を32秒から減らす |
| 36〜38秒 | 「終了」を表示。残ったチャレンジは帰還まで進める |
| 38秒以降 | 結果画面。BGMは止めず、約40秒までアウトロが流れる |

結果への遷移はBGMの再生完了を待たない。「タイトルへ戻る」でタイトル画面へ戻り、改めて「スタート」を押すと、出現場所を選び直して得点と時間をリセットする。

残り時間は秒単位で切り上げ、下限は0秒とする。終了表示中も、残っているチャレンジの出現中・停止中は叩けて加点される。本編内の最後の出現は31秒で、通常の帰還完了は本編開始から32.3秒、命中のタイミングによっては約32.6秒まで続く。

### チャレンジ

**モグラが穴から出始めて、穴へ戻りきるまでの一連の動き**を「1チャレンジ」とする。命中リアクションも含める。

```text
通常：出現 → 出きった位置で停止 → 帰還 → 完了
命中：出現中または停止中に命中 → リアクション → 帰還 → 完了
```

現在は150msで出現し、1,000ms停止して、150msで帰還する。出る速度と引っ込む速度は同じ。出現中・停止中の、見えているモグラを叩ける。帰還中は叩けない。命中後は通常の進行を止めてリアクションし、その後、残りの距離に合わせて通常と同じ速度で帰還する。

### 出現譜面

120 BPM・4拍子の16小節を、八分音符128枠で表す。1枠は250ms、各行は4小節・8秒。`1`は1体の出現開始、`0`は出現開始のない枠を表す。

```text
1000 0000 1000 0000 1000 0000 1000 0000
1000 0010 1000 0010 1000 0010 1000 0010
1000 1010 1000 1010 1000 1010 1000 1010
1010 1000 1111 1000 1010 1000 1111 1000
```

各8秒区間の出現数は4・8・12・16体、合計40体。出現開始時刻が異なっていても、前のモグラが残っていれば同時に見える。

## 3. 画面・操作

スマホの縦画面・タッチ操作を基本とし、PCではマウスでも操作できる。

| 画面 | 内容 |
| --- | --- |
| タイトル | 仮タイトル、短い遊び方、スタートボタン |
| イントロ | よーい、3・2・1 |
| プレイ | 残り時間、スコア、穴とモグラ |
| 終了表示 | 終了、帰還中のモグラ |
| 結果 | 最終スコア、タイトルへ戻るボタン |

ゲーム全体は5:8。375 × 600pxを基準とし、上112pxをヘッダー、中央375pxを盤面、下113pxをボタン領域としてレイアウトする。看板と文字はヘッダーの基準位置から40px下げて配置する。プレイ中もボタン領域を保持し、画面遷移でCanvas・フッターの位置やページの高さを変えない。リポジトリへのリンクはCanvasの外側・下部に置く。

| 項目 | 方針 |
| --- | --- |
| ブレークポイント | 768px未満はSP表示、768px以上はPC表示 |
| SP | 基準幅375px。中央コンテンツは画面幅に合わせて拡縮する |
| PC | デザイン基準幅1200px。中央コンテンツは幅500pxで中央配置する |

タイトル・結果画面では、Canvas上からもページをスクロールできる。イントロから終了表示まではゲーム領域のタッチスクロールを抑止する。PCのホイールによるスクロールは常に可能とする。

盤面は、手前のモグラが後ろの穴やモグラに重なるくらいの配置を目指す。見た目もタップの判定範囲も重なりを許容し、見えているモグラを基準にスマホで狙いやすい大きさへ調整する。

## 4. 見た目・アニメーション・音声

### 背景と装飾

上から空・緑・畑の土・明るい道を重ねる。空の左右に小さな雲を置き、空と緑の境界には低い茂みと植物を重ねる。植物の葉は明るい空・緑の下地・茂みに合わせて明るく鮮やかな緑とし、濃淡を残す。葉脈は葉より濃い緑にする。

畑の端にニンジン、畑と道の境目に低い丸太、道のボタンの両脇に薄い足跡を添える。ニンジンは葉と根の肩だけを地上に出し、根元に土を重ねる。左上3本・右上2本・左下2本・右下1本を、大きさ・間隔をずらして配置する。ニンジンの葉と柱の根元の草にも共通の葉色を使う。

畑には小石を少量置き、穴の開口部とその周囲は空ける。装飾の位置はプレイ中・再プレイ時とも固定し、中央の操作領域と文字・ボタンの周囲を空ける。

### 看板と文字

タイトルから結果画面まで共通の木の板を常設する。375px基準で幅295px・高さ96px、左40px・上48px。左右の背景を見せ、文字の背面は明るく保つ。少し不揃いな縁・下端の厚み・控えめな横方向の木目と節を描く。

板の裏には2本の木の柱を立てる。柱は上側の野菜より手前に置き、根元に土と小さな草を重ねて地面に差し込まれた見た目にする。ボタンは通常のUIとして扱う。

残り時間とスコアは各64px幅の2列とし、板の内側に余白を均等に配分する。見出しは各列の中央揃え、数値と単位は右揃え。結果画面では「結果」と点数の間に追加のマージンを設けず、2行をひとまとまりとして看板内の上下中央に置く。

書体はGoogle Fontsの「M PLUS Rounded 1c」Bold（700）で、ボタンと数値も共通にする。

### 穴とモグラ

現在は図形と簡単な目・口による仮グラフィックを使う。穴は楕円。モグラは地面より上と穴の内側で見え、手前の縁より下は地面に隠れる。顔の後ろには下へ続く胴体を描き、停止中・命中時も体が穴からつながって見えるようにする。

命中時は目を×にして口を開き、横に広がって縦につぶれる。変形は片道90ms、つぶれた状態で120ms停止してから元に戻り、帰還する。次のチャレンジでは通常の表情に戻す。

### 命中エフェクト

命中したタップ位置に星を100ms表示し、続いて短い線が集まった放射線を200msかけて拡大・フェードアウトする。全体で300ms。放射線は画像全体を変形させ、長さ・太さ・間隔を一緒に変える。既存の命中リアクションと重ね、盤面の前面に表示する。空振りや命中済みのモグラへの再タップでは出さない。

星と放射線は128 × 128px・透過背景・中心を揃えた2枚の仮素材。指で隠れにくいサイズとし、素材に対する倍率は星が0.56 → 0.8、放射線が0.64 → 1.44。表示位置はタップ位置のままとする。

### 音声

BGMは120 BPM・4拍子で、イントロ2小節・本編16小節・アウトロ2小節の計40秒。画面との対応は「2. ルールとプレイの流れ」にまとめる。コード・音色・作曲の意図は[作曲メモ](audio-composition-notes.md)を参照。

スタート操作でBGMを先頭から再生する。結果画面やタイトル画面へ戻っても残りのBGMは流し続け、次のスタートで前回のBGMを止めて先頭から再生する。

出現開始時と命中リアクション開始時に、それぞれSEを1回再生する。空振りや同じチャレンジへの重複タップでは命中音を鳴らさない。複数の出現・命中が続いた場合は、それぞれの音を重ねて再生する。

## 5. 実装の仕組み

Vite + TypeScript + Phaserを使用する。Phaserの標準機能を活用し、ゲーム部分をPhaser、文字・ボタンをHTML/SCSSで実装する。複雑な仕組みや過度な共通化を避け、時間や間隔は調整しやすい定数にまとめる。

### 描画とレイアウト

Phaserのゲーム座標は375 × 600px、Canvasの描画解像度は750 × 1200px。カメラを2倍に拡大して座標を保ち、Canvas全体を中央コンテンツの表示幅へ拡縮する。HTMLのUIは透明なレイヤーとして重ねる。空白部分はタップを透過し、ボタンだけが操作を受け付ける。ボタンを隠す際は`visibility: hidden`で領域を保持する。

SCSSの`sp-and-pc-block`は、SPデザイン上のpx値からSP用のvw値とPC用のpx値を生成する。`mq-pc`の切り替え幅は768px。

- SP：`SPデザイン上のpx値 ÷ 375px × 100vw`
- PC：`SPデザイン上のpx値 × (500 ÷ 375)`

例えば75pxはSPで20vw、PCで100pxになる。HTMLと盤面の表示スケールを揃える。

背景は`gardenBackground.ts`、装飾は`gardenDecorations.ts`で、初期化時にPhaserのGraphicsで描く。主な基準位置は次のとおり。

| 対象 | 375 × 600px基準の位置 |
| --- | --- |
| 空と緑の下地の境界 | y = 72 |
| 緑と土の境界 | y = 148付近の曲線。緑の高さは約76px |
| 土と道の境界 | y = 491付近の緩い曲線 |
| 看板の柱 | x = 102・273、y = 123〜206 |

低い茂みは下地より手前、植物と小石は接地位置のY座標をdepthにする。穴・モグラのコンテナも穴の中心Y座標をdepthに使い、手前の物が奥の物を覆う。柱はdepth = 206で上側の野菜より手前に置き、上端をHTMLの板で隠す。装飾には当たり判定を付けない。HTMLのUIと命中エフェクトは盤面より前面に置く。

穴の下半分の輪郭に沿った地面色の図形を、モグラの手前に重ねる。地面の幅は穴と同じ幅に絞り、隣の穴を覆わないようにする。道にかかる部分も背景と同じ色・境界に揃える。タップ判定は、地面より上または穴の内側の、見えているモグラの範囲に合わせる。

TypeScriptとSCSSの色は`colors.ts`の`COLORS`で用途ごとに管理する。UIの色は起動時にCSSカスタムプロパティへ設定し、同じ色値でも用途ごとに独立して調整できる。SVGの色は各素材内、透明度は各描画箇所で管理する。

Google Fontsは`display=swap`で読み込み中に代替書体を表示する。文字の絞り込みや、数値用の明示的なプリロードは行わない。

### 状態と役割分担

| 担当 | 役割 |
| --- | --- |
| `ChallengeScene` | プレイ全体の進行、得点、音声、各Moleへの操作の振り分け |
| `Challenge` | 1チャレンジの時間・状態・命中受付を管理 |
| `Mole` | 1マス分の描画・Tween・当たり判定 |
| `GameUI` | HTMLの表示切り替え、得点・時間、ボタン、タッチスクロールの切り替え |

プレイ開始時に設定配列から`challengeParams.map(params => new Challenge(this, params))`でインスタンスを生成する。`challenges`は開始時刻順の進行表で、更新が飛んでも同じマスの前のチャレンジを先に完了できる。Moleは9個の配列として持ち、`moleIndex`で操作対象を指定する。

`Challenge`は進行段階の`phase`（`idle`・`emerging`・`waiting`・`returning`・`completed`）と、命中済みかを示す`isHit`を別に管理する。完了後も命中結果を保持し、次のプレイでは進行表を作り直す。

Sceneは`ChallengeContext`を実装する。各Challengeに`onUpdate(elapsedMs)`で時間を渡し、Challengeは`emergeMole()`・`holdMole()`・`showHitReaction()`・`returnMole()`・`hideMole()`を通して演出を依頼する。命中を受け付けたときだけ`addScore(1)`を呼ぶ。

`emergeMole(moleIndex, durationMs, onTap)`にはChallengeのタップ用コールバックを渡す。Moleは出現時にリスナーを登録し、当たり判定を通った入力を通知する。Sceneが経過時間を付け、Challengeの`onTap(elapsedMs)`へ渡す。リスナーは命中・帰還・非表示・破棄時に解除し、次の出現で登録し直す。

`canHit()`は「出現中または停止中、かつ未命中」を判定する。命中時は`phase`を保ったまま`isHit`を更新し、通常の進行を止めてリアクションする。その後帰還へ進む。各段階の時間はChallengeが管理し、SceneのTween完了通知で状態を操作しない。

Moleは演出の依頼を受ける際に直前のTweenを解除する。出現・帰還は独立したTween、命中時のつぶれて元に戻る動きは`yoyo`で表現する。命中エフェクトはモグラの移動・変形とは別に表示する。

### スケジュールの生成

同じマスの競合を避けるため、1件につき出入り・停止・命中リアクションを含む最大所要時間を予約する。現在は`150 × 2 + 1,000 + 90 × 2 + 120 = 1,600ms`。早く完了しても次の開始時刻は変えず、予約終了時刻と次の開始時刻は一致してよい。

1. 譜面を時刻順に読み、`1`のある枠の番号 × 250msを開始時刻とする。
2. その時刻に予約が空いているマスから、ランダムに1個選ぶ。
3. 開始時刻から1,600ms後までを、そのマスの予約とする。

生成中はマスごとの直前の予約終了時刻を管理する。空きマスがなければ、時刻をずらさず生成エラーにする。予約管理は生成関数内で完結し、MoleやChallengeに予約表を持たせない。

### 音声と進行時間

| 用途 | 素材 |
| --- | --- |
| BGM | `src/assets/audio/bgm.mp3` |
| 出現音 | `src/assets/audio/mole-emerge.mp3` |
| 命中音 | `src/assets/audio/mole-hit.mp3` |
| 命中エフェクト | `src/assets/fx/hit-star.svg`・`hit-rays.svg` |
| 看板 | `src/assets/sign-board.svg` |

音声再生がロックされている場合は、解除後にBGMと進行を始める。再生中はBGMの再生位置を基準とし、本編の経過時間はそこからイントロの4秒を引いて求める。音源が先に終わった場合はゲーム側の経過時間で進行を続ける。

Scene終了時にはBGMを破棄し、出現音・命中音も停止する。

## 6. 未決定・今後検討すること

- キャラクターの設定、出現する理由、野菜との関わり、最終的な美術表現。
